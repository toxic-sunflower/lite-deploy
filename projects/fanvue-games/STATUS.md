# FanVue Games: сервер и деплой, состояние

Обновлено 2026-10-24. Знания лежат вне репозитория приложения намеренно (репозиторий не должен подсказывать устройство сервера). Очередь: `TODO.md`, решения: `decisions.md`, схема и разовая настройка: `README.md`.

## Сервер

Ubuntu 26.04, общий с другими проектами, адрес и ход ручной настройки в `../../WALKTHROUGH.md`. Подготовлено вручную по шагам: обычный пользователь с ключом, обновления и автообновления безопасности, `ufw` (22, 80, 443), `fail2ban`, время (`chrony` из коробки), podman 5.7, PostgreSQL 18 (только localhost), Caddy из официального репозитория (пустой, с `conf.d`), вход под root по SSH закрыт, пользователь проекта `fanvue-games` (linger включён), роль и база `fanvue_games` (доступ через сокет, правило в `pg_hba.conf`), файл `app.env` со строкой подключения.

## Деплой

Готово в файлах (этой папки и workflows репозитория), на сервере не применено, кроме привратника (лежит в `/home/fanvue-games/bin/`, версия старая, заменить): `bin/` (blue-green скрипт для сервиса и админки вместе, привратник), `quadlet/` (юниты слотов blue и green для сервиса и для админки), `caddy/` (сайт сервиса на `127.0.0.1:18080`, сайт админки на `127.0.0.1:18090`, запасной файл для сбоя Cloudflare), `github-actions/` (копии workflows `deploy.yml` и `rollback.yml`, настоящие лежат в репозитории приложения). Выкатка выключена, пока не задана переменная репозитория `DEPLOY_ENABLED=true`.

Проверено: скрипты в песочнице (подставные podman, systemctl, curl): 29 проверок (деплой, второй деплой, откат, сломанная админка, отказ Caddy, команды привратника).

Не проверено: файлы Caddy настоящим Caddy; вся цепочка на сервере и на GitHub (`deploy.yml` не запускался, на раннере нужен SDK 10); подключение контейнера к PostgreSQL хоста через сокет проверено локально, на сервере нет; запасной план.
