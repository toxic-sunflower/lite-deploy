# FanVue Games: сервер и деплой, состояние

Обновлено 2026-10-25. Знания лежат вне репозитория приложения намеренно (репозиторий не должен подсказывать устройство сервера). Очередь: `TODO.md`, решения: `decisions.md`, схема, команды и разовая настройка: `README.md`.

## Сервер

Ubuntu 26.04, общий с другими проектами, адрес и ход ручной настройки в `../../WALKTHROUGH.md`. Подготовлено вручную по шагам: обычный пользователь с ключом, обновления и автообновления безопасности, `ufw` (22, 80, 443), `fail2ban`, время (`chrony` из коробки), podman 5.7, PostgreSQL 18 (только localhost), Caddy из официального репозитория (с `conf.d`), вход под root по SSH закрыт, пользователь проекта `fanvue-games` (linger включён), роль и база `fanvue_games` (доступ через сокет, правило в `pg_hba.conf`).

## Что сделано на сервере по проекту (2026-10-24 и 25)

- Привратник `fanvue-ssh-gate` (новая версия), скрипт `fanvue-deploy`, четыре юнита Quadlet (`daemon-reload` выполнен, юниты видны).
- Ключ деплоя в `authorized_keys` с принудительной командой и `restrict`; закрытая часть в секрете GitHub, файл на компьютере удалён.
- Правило `sudoers` (`/etc/sudoers.d/fanvue-games-caddy`): только `systemctl reload caddy`.
- Файлы настроек: `deploy.conf`, `admin.env`, `app.env` (в том числе `Auth__SessionSecret` и значения `Fanvue__*`; `Fanvue__WebhookSecret` может быть пустым, пока не зарегистрирован вебхук).
- Вход в GHCR под `fanvue-games` (токен с правом `read:packages`, `--authfile` в постоянном месте).
- Caddy: каталоги `/etc/caddy/upstreams` и `/var/log/caddy`, начальные upstream-файлы (`503 not deployed`), два файла сайтов в `/etc/caddy/conf.d/` на домене `prozorov.site`, проверка и `reload`.
- Туннель `cloudflared`: пакет из официального репозитория, служба под отдельным пользователем `cloudflared`, токен в `/etc/cloudflared/tunnel.env` (root, 600), два маршрута (`fanvue-games.prozorov.site` → `http://localhost:18080`, `admin.fanvue-games.prozorov.site` → `http://localhost:18090`). Туннель Healthy, сайт по имени доходит до Caddy (отвечает заглушкой).

## Первая выкатка (2026-10-25)

Не завершена. Цепочка (привратник, скрипт, скачивание образов, запуск слота) отработала; сервис в слоте blue стал готов, **админка нет**: несовпадение версий `Microsoft.EntityFrameworkCore.Relational` (10.0.4 в админке против 10.0.12 у общего проекта). Скрипт остановил слот, трафик остался на заглушке `not deployed`. Исправление (явная версия пакета в общем проекте) проверено локально публикацией админки, но **ещё не в `main`**: нужен коммит, PR и слияние, затем новый запуск деплоя.

## Не проверено

- Вся цепочка до конца (успешный деплой, переключение Caddy на слот, второй деплой, откат).
- Живые проверки Caddy: заголовки (`X-Forwarded-For` из `CF-Connecting-IP`), лимиты тел запросов (413 на 6 МБ, загрузка в Vault проходит), переключение upstream после `reload`.
- Поведение при сбое миграции (по коду и скрипту трафик остаётся на старой версии, живой проверки не было).
- Запасной план Cloudflare, Cloudflare Access для админки, правило для вебхука.
- Изоляция проекта на сервере (чек-лист в `../../DEPLOY-PATTERN.md`), отсутствие секретов в `/etc/environment` и истории.
- Реальная интеграция с Fanvue (адрес опыта на домене, вебхук, оплата).
