# FanVue Games: сервер и деплой, очередь работ

Это знания об инфраструктуре проекта. Они **намеренно лежат вне репозитория приложения**: репозиторий не должен подсказывать, как устроен сервер. Папка `projects/<проект>/` задумана как образец для будущей системы развёртывания разных проектов (см. `../../VISION.md`).

Идём по шагам вручную, с объяснением каждой команды (владелец хочет понимать, что делает). Описание схемы и команды: `README.md` рядом, решения: `decisions.md`, состояние: `STATUS.md`. Запуск на боевом домене: неделя после 2026-10-24.

## До боевого запуска

- [ ] **Cloudflare Access для админки** (`admin.fanvue-games.prozorov.site`): Zero Trust → Access → Applications, правило по почтам. До этого имя админки не открывать. Уточнить, просит ли Zero Trust привязать карту.
- [ ] Правило Cloudflare для `POST /api/webhooks/fanvue` (пропуск проверок ботов). Затем зарегистрировать вебхук в Fanvue и вписать `Fanvue__WebhookSecret` в `app.env`.
- [ ] Проверить `Fanvue__RedirectUri` и адрес опыта у Fanvue на новом домене (`https://fanvue-games.prozorov.site/api/auth/callback`, `…/fan/hub`).
- [ ] Прогнать запасной план (`caddy/fanvue-games.fallback.caddy.disabled`, раздел «Если Cloudflare недоступен» в `README.md`): включить, проверить, вернуть.
- [ ] Живая проверка Caddy на сервере: чужое имя на порту сайта ничего не отдаёт (проверка с `Host: чужое.example`), `X-Forwarded-For` берётся из `CF-Connecting-IP`, лимиты тел запроса (413 на 6 МБ, загрузка в Vault проходит), переключение upstream после `reload`.
- [ ] **Учебный сбой миграции:** убедиться на практике, что при падении миграции новый слот останавливается, а трафик остаётся на старой версии, и записать результат (сейчас это выводится из кода и скрипта, не проверено).
- [ ] Проверка изоляции после первой выкатки: из контейнера достать `localhost:2019` (API Caddy) и другие порты хоста; из-под `fanvue-games` попробовать подключиться к другим базам и к `postgres` (должно не пускать); просмотреть `pg_hba.conf` (`sudo grep -v '^#'`) на правила с `all`. `admin off` в Caddy ставить нельзя (ломает `systemctl reload caddy`), при необходимости переводить API на unix-сокет и проверять reload.
- [ ] Проверка, что секреты нигде не светятся (на сервере, только чтение): `/etc/environment`, `/etc/profile.d/`, `/etc/systemd/system.conf.d/` и `~/.bash_history` пользователя `serafim` на пароли и токены (`grep -i -E 'password|secret|token|PW='`); что `app.env`, `admin.env`, `deploy.conf` с правами 600 и владельцем `fanvue-games`, `/etc/cloudflared/tunnel.env` с правами 600 и владельцем root.
- [ ] 2FA на аккаунте GitHub (защита секретов окружения `production`).
- [ ] Консоль хостера как запасной вход: выяснить, есть ли, до отключения входа по паролю.
- [ ] Отключить вход по паролю в SSH (`PasswordAuthentication no` в `/etc/ssh/sshd_config.d/00-hardening.conf`) после проверки входа по ключу (вторая сессия!) и наличия консоли.
- [ ] Очистка старых образов в GHCR (бесплатно около 500 МБ приватных пакетов; каждый деплой кладёт образы с тегом-хэшем): оставлять последние 10 или около того.
