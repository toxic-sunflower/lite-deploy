# Как это устроено (черновик, 2026-10-30)

Файл собирает решения из обсуждений. Обоснования ниже простыми словами. Где что-то не решено, так и написано. Принципы проекта: `VISION.md`.

## 1. Что это одной фразой

На сервере работает маленькая программа (агент). Через неё владелец, CI и ИИ-помощник настраивают сервер и выкатывают проекты, не получая полного доступа к серверу.

## 2. Из чего состоит

1. **Агент.** Программа на сервере, работает постоянно (служба systemd). Принимает запросы, проверяет, кто спрашивает и можно ли ему, и выполняет.
2. **Плагины.** Каждый умеет одно: `base` (защита сервера), `postgres`, `caddy`, `podman` или `docker`, `cloudflare-tunnel`. Плагин знает, как поставить, настроить и проверить свою часть.
3. **Описание проекта.** Один небольшой файл: имя, домен, образ, нужна ли база, лимиты. Из него агент делает всё остальное.
4. **Состояние на сервере.** Список проектов, настройки, журнал действий. Секреты лежат в файлах проекта с правами 600. В GitHub и GitLab ничего этого нет.
5. **Клиенты.** Программы, которыми вы управляете агентом: командная строка (CLI), MCP для ИИ, в будущем веб. Они тонкие и ничего не решают сами, всё решает агент.

## 3. Как к агенту обращаются

| Кто | Как | Что разрешено |
|---|---|---|
| Владелец | Входит на сервер по SSH, работает через CLI | Всё |
| CI (GitHub Actions) | Ограниченный SSH-ключ | Только `deploy <хэш>`, `rollback`, `status` одного проекта |
| ИИ-помощник | MCP, ограниченный токен | Безопасные действия. Опасные ждут подтверждения владельца |
| Пользователь проекта | Локально на сервере | Только свой проект |

Агент не слушает интернет. Он слушает только локальный сокет, до которого можно добраться, войдя на сервер.

## 4. Безопасность: четыре уровня

| Уровень | Как работает | Безопасность | Удобство |
|---|---|---|---|
| 0 | Всё руками | максимум | нет |
| 1 | Агент без прав готовит план. Всё, что требует root, выполняет владелец командой `sudo` | очень высокая | среднее |
| 2 | Две программы: первая без прав принимает запросы, вторая с root умеет только фиксированный список действий | высокая | высокое |
| 3 | Одна программа с root делает всё | слабая | высокое |

**Предлагаемый выбор: уровень 2 по умолчанию, уровень 1 как режим «параноик».**

Чем это отличается от конкурентов (Coolify, Dokploy, Kamal):
- У них, взломав панель, получают ключ, которым можно выполнить **любую** команду на сервере.
- У нас на уровне 2, взломав программу без прав, можно попросить только то, что есть в списке (создать пользователя, перезагрузить Caddy, создать базу). Произвольную команду от root выполнить нельзя.
- Остаточный риск есть: ошибка в маленькой root-части. Поэтому она должна быть крошечной, проверяемой и не разбирать сложный ввод.

Дополнительно: опасные действия (удалить базу, показать секрет) требуют подтверждения владельца вне канала ИИ. Все действия пишутся в журнал. Установка и обновление агента и плагинов только по команде владельца, с проверкой подписи.

## 5. Как агент получает настройки

- **Сейчас:** по запросу клиента (CLI, MCP) через локальный API агента.
- **Возможно позже:** агент сам периодически забирает описание желаемого состояния из внешнего хранилища. Это безопаснее, чем присылать команды, потому что конфиг это данные, а не код: агент принимает только известные поля, проверяет каждое и ничего не исполняет. Но источник нужно защитить (TLS, подпись вашим ключом), секреты в конфиг не класть, опасные изменения подтверждать. Вопрос, где хранить такой конфиг, не решён, потому что описание инфраструктуры нельзя класть в GitHub или GitLab.

## 6. Что решено

- Агент лёгкий, интерфейса в нём нет, клиенты отдельно.
- Плагины: Caddy, Postgres (на хосте по умолчанию или в контейнере), Podman и Docker, Cloudflare Tunnel.
- Проект можно описывать через compose или Quadlet, в одном проекте можно смешивать.
- Балансировщик: абстракция из трёх понятий (`Route`, `Backend`, `Listener`), по умолчанию Caddy.
- Каталога сервисов не делаем, формат шаблонов закладываем. Шаблон: данные без скриптов.
- Состояние и секреты только на сервере, нужен шифрованный бэкап и восстановление.
- Пока один сервер.

## 7. Что не решено

1. **Уровень безопасности по умолчанию:** 2 (моё предложение) или 1?
2. **Режим «агент сам забирает конфиг из внешнего хранилища»:** нужен ли и где хранить, или хватит локального API?
3. **Язык агента:** Go (проще писать плагины и вызывать системные утилиты) или Rust (больше гарантий по памяти).
4. **Как подтверждать опасные действия:** через интерактивную SSH-сессию владельца или через Cloudflare Access в вебе.
5. **Плагины внутри бинарника** (моё предложение: проще и безопаснее) или отдельными программами.

## 8. Словарь

- **Демон, служба** — программа, которая работает в фоне постоянно.
- **Root** — пользователь с полными правами на сервере.
- **Сокет** — «файл-розетка» на сервере, через который программы общаются друг с другом. Из интернета он недоступен.
- **Плагин** — модуль, который умеет настраивать одну часть системы.
- **План и применение** — сначала агент показывает, что изменит, потом изменяет, потом проверяет.
- **Декларативный конфиг** — описание того, что должно быть, а не последовательность команд.
- **MCP** — способ подключить ИИ-помощника к инструменту.
