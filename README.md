# Установка ПО на сервер (черновики)

Скрипты для голого сервера **Ubuntu 24.04 или новее**. Они ставят только ПО и базовую защиту. Приложение, пользователи проекта, роль и база в PostgreSQL, сайт в Caddy, службы podman и деплой делаются отдельными шагами позже.

Этот набор живёт отдельно от репозиториев проектов: сервер общий. Исходники и git на сервере не нужны, копируются только эти скрипты. Образы приложений будут собираться в GitHub Actions и скачиваться сервером.

## Что ставится

| Шаг | Скрипт | Что делает |
|---|---|---|
| base | `01-base.sh` | Обновления, автоматические обновления безопасности, брандмауэр (`ufw`: снаружи только SSH, 80, 443), `fail2ban`, синхронизация времени. По флагу `--harden-ssh` отключает вход по паролю и под root |
| podman | `02-podman.sh` | podman для запуска без root, службы пользователя systemd |
| postgres | `03-postgres.sh` | PostgreSQL 18 из официального репозитория PGDG, слушает только localhost |
| caddy | `04-caddy.sh` | Caddy из официального репозитория. Главный `Caddyfile` только подключает `/etc/caddy/conf.d/*.caddy`: сервер общий, у каждого проекта свой файл |
| проверка | `verify.sh` | Только читает: брандмауэр, службы, SSH, что PostgreSQL не слушает наружу, что слушает сервер |

`install.sh` запускает все шаги по порядку и в конце `verify.sh`.

## Перед запуском

1. Заведите на сервере **обычного пользователя с `sudo`** и войдите им по SSH-ключу. Под root скрипты тоже работают, но защита SSH (`--harden-ssh`) запрещает вход под root и требует обычного пользователя с ключом.
2. Скопируйте скрипты с вашего компьютера (git на сервере не нужен):

```bash
scp -r server-setup пользователь@сервер:~/server-setup
```

3. Прочитайте скрипты. Они небольшие, и вы запускаете их с правами root.

## Запуск

Установить всё:

```bash
cd ~/server-setup && sudo bash install.sh
```

Только отдельные шаги, например PostgreSQL и Caddy:

```bash
sudo bash install.sh --only postgres,caddy
```

### Защита SSH (отдельно и осторожно)

Отключает вход по паролю и под root. Если у пользователя нет ключа, скрипт откажется. После включения **не закрывайте текущую сессию**: откройте вторую и проверьте, что вход по ключу работает.

```bash
sudo bash install.sh --only base --harden-ssh
```

## Проверка

```bash
sudo bash verify.sh
```

Должно быть: ufw включён, `fail2ban`, `chrony`, `caddy`, `postgresql` работают, PostgreSQL слушает только localhost, снаружи открыты только SSH, 80 и 443. Строки `FAIL` значат серьёзную проблему, `WARN` стоит разобрать.

## Чего скрипты намеренно не делают

- Не создают пользователя проекта, роль и базу в PostgreSQL, сайт в Caddy, службы приложений (следующие шаги).
- Не открывают PostgreSQL и админку наружу.
- Не перезагружают сервер сами после обновлений (при обновлении ядра перезагрузите вручную).
- Не трогают чужие настройки: главный `Caddyfile` сохраняется копией `Caddyfile.bak.<время>`.

## Что дальше (по порядку)

1. Пользователь проекта и rootless podman, роль и база в PostgreSQL, доступ контейнера к базе.
2. Сайт проекта в `/etc/caddy/conf.d/`, заголовки безопасности, админка только локально.
3. Службы приложений (Quadlet) и вход сервера в реестр образов GHCR.
4. GitHub Actions: сборка образов и деплой по SSH с ограниченным ключом.
